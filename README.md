# スタンスメモ 独立試作版

公開URL： https://kanon6343.github.io/snowboard-stance-memo-trial/

正式版の /snowboard-stance-memo/ に含まれない場所で試作をインストールできるようにするコピーです。既存の正式版・試作版は変更せずに残します。v2.5.1（試作）、キャッシュ更新1093。

## 公開

このフォルダの中身を新規リポジトリ snowboard-stance-memo-trial のルートへ配置し、GitHub Pages を main ブランチの / (root) から公開します。URLは公開後に検証します。

## データ

同一ブラウザー・同一オリジンであれば haru-detail: の既存データを参照します。別ブラウザーや別ストレージ環境には自動同期しません。既存の試作版でバックアップを書き出しておくと、必要に応じて新しいアプリで復元できます。公開先の分離だけでは同一オリジンのデータ領域は完全には分離されません。

## インストール

新しい試作URLをブラウザーで開き、オフライン準備の完了後、インストール／ホーム画面へ追加します。正式版とはアプリの範囲を重ねない構成です。端末ごとの実機確認は別途行います。

## スタンス幅の検索

「探す」のスタンス幅は「ぴったり／範囲」で切り替えます。ぴったりは53など1つの数値を指定し、53.0は53と同じ幅として扱います。空欄は条件なし。範囲は従来どおり下限・上限を含みます。以前保存した範囲条件は範囲として引き継ぎます。簡易・詳細入力の両方で使え、検索は履歴本体を変更しません。

詳細入力の「探す」では、板の形状（シェイプ・ノーズ形状・ベンド）を折りたたまず常時表示します。簡易入力では非表示です。

更新時は画面HTMLもHTTPキャッシュの再検証を行ってからオフライン用に保存し、連続更新で古い画面が新しいキャッシュに残ることを防ぎます。

## 更新先の表示

更新待ちのService Workerへ直接問い合わせ、更新先の版番号を通知と更新ボタンに表示します。取得できない旧形式の更新は、版番号を推測せず通常の更新ボタンを表示します。今回の機能を読み込んだ後の更新から利用できます。

## 入力と保存履歴のスワイプ

本文を左へ払うと入力から保存履歴へ、右へ払うと保存履歴から入力へ戻ります。タブのタップも使えます。入力途中の値や編集中の内容はそのまま保持し、スワイプで履歴を保存・変更することはありません。画面内の位置は同じ起動中のスワイプ移動で戻れるようにします。

入力欄、ボタン、リンク、ビス穴、左右足の切替、履歴の表示形式、横スクロール部分は対象外。縦スクロール・ピンチとメニューを開く端の操作を優先します。確認画面・ガイド・下書き復元の案内中、メニューを開いている間は画面移動しません。履歴のカード／詳細一覧／板ごとはタップのままです。

メニューで簡易／詳細入力を実際に切り替えた時はメニューを閉じます。起動・下書き復元・ガイドなどのプログラムによるモード変更では閉じません。

## v2.2.1の修正

- 復元したIDを文字列へ正規化し、不正な値や重複は採番し直して全記録を維持。HTMLへ表示するIDもエスケープします。保存済みの数値IDも呼び出し・お気に入り・削除で扱えます。
- 削除直前に最新の記録とお気に入り保護を確認。重複・削除済み・別画面で変更済みの対象は成功扱いせず中止します。既存の重複IDはバックアップを書き出し、上書き復元することで整理できます。起動だけで履歴を書き換えることはありません。
- 履歴が読み取れない場合は通常のバックアップを中止し、元データの退避へ案内。正常な0件のバックアップは維持。
- 日時順は時差表記を含めて実際の時刻で比較し、日時不明は昇順・降順とも末尾へ。

## v2.3.0：更新内容の表示確認

メニュー→データの現在のバージョン直下に、初期状態で閉じた更新内容を表示します。更新待ちの版が説明を提供する場合、適用前にも「更新内容を見る」で確認できます。説明は実際の待機中Service Workerから取得し、HTMLとして解釈せず表示します。版が変わった時は古い説明を消し、説明取得だけで更新・再読み込み・履歴の書き換えは行いません。

v2.2.1以前の画面には説明欄がないため、この版へ更新してから表示できます。以後の更新では適用前・適用後の両方で確認できます。説明のない古い版や取得失敗時も、版番号や従来の更新操作は維持します。

## v2.3.1：更新前の説明を確認するテストパッチ

v2.3.0の画面で「最新版を確認」すると、適用前に「更新内容を見る」でこの版の説明を確認できます。保存履歴・入力項目・設定値・更新処理そのものは変更していません。

## v2.3.2：メニューを開く開始範囲

端から24 CSS pxだった開始位置を、画面幅の20%・最大72 CSS pxまで拡大。左右配置とも対応します。透明な端の要素は24pxのままで入力欄を覆いません。広げた部分のタッチ操作は非passiveなtouchmoveで横方向を判定し、縦スクロール・複数の指・キャンセルは元の操作を優先します。入力欄、ボタン、リンク、横スクロール領域、マウスでの文字選択は対象外です。

入力と履歴のスワイプは、開始範囲内でメニューを引き出す方向に動いた場合だけメニューへ委譲します。反対方向や開始範囲の外では従来の画面移動を維持します。保存内容・キー・PWAの識別情報は変更しません。

## v2.3.3：短い画面スワイプとメニュー全体からの格納

入力・保存履歴の切り替えは、ゆっくりなら最大40 CSS px、素早いフリックなら24 CSS pxから反応します。横方向の判定、縦スクロール、入力欄などの除外と画面端のメニュー優先は維持します。

メニューの「探す」は、本文だけでなく見出し・上のタブ・背景からも閉じる方向へ払えます。「表示」「データ」の本文はタブ切り替えのまま、本文以外からは閉じられます。入力欄、横スクロール、確認画面、ガイド、複数指は対象外です。TouchEventsとPointerEventsの二重処理を避け、タップ操作を維持します。


## v2.5.0：雪山の天気（はるくん試作）

メニュー→表示→「天気とおすすめ候補を見る」。19地点・7日間の新雪、気温、風を比較し、日付・エリア・お気に入り・バランス／新雪重視／晴れ重視で候補を表示します。営業状況やリフト運行は判定せず、各公式サイトへ案内します。

天気は端末からOpen-Meteoへ直接リクエスト。標準の自動選択モデルへ接続できない場合はGFSアンサンブルのコントロール予報に切り替え、出典を表示します。予報は表示標高付近の予想値で、ゲレンデの実測積雪ではありません。朝の新雪は前日9時より後〜当日9時まで24個の時間値の合計、日中は9〜15時。欠測値は0にせず—を表示します。

新しい設定・予報キャッシュはharu-detail:mountain-weather-*だけを利用し、既存の履歴・入力・バックアップは変更しません。予報キャッシュは1時間で再確認、6時間以上前はおすすめ対象外。APIの応答はこの端末だけに保存し、GitHubへ個人データを送りません。

Weather静的ファイルをオフラインSHELLに含め、weather/とweather/index.htmlの両方を独立したページとして復元します。予報未取得の初回オフライン時は未取得として表示。気象APIはService Workerでキャッシュせず、予報の取得日時と失敗状態を表示します。

予報データ：[Open-Meteo](https://open-meteo.com/)・[CC BY 4.0](https://open-meteo.com/en/licence)。独自の集計・比較で、気象機関の推奨や運休基準ではありません。


## v2.5.1：エリアが決まっている時の天気画面3案

現在の天気画面の下部「3つの画面案を比べる（サンプル）」、または weather-design-lab/ から開きます。

①エリア一覧：同じエリアのスキー場を行で比較し、必要な場所だけ展開。②横並び比較：最大3地点の同じ項目を表に並べる。③スポット詳細：1地点の1週間・時間帯と同エリアの他の場所を見る。白馬・湯沢／南魚沼・奥美濃・ニセコ／ルスツの4エリア、16地点の架空の数値を使います。実際の予報・営業情報として使わないでください。

案の切り替え、エリア、日付、比較対象、お気に入りは試作用のharu-detail:weather-design-lab-v1だけに保存します。実際の予報キャッシュ、板・スタンス履歴、下書きは変更しません。比較画面から外部APIへの通信はありません。?view=list / compare / spot の直リンクも使えます。

3案は別ページでの検討用で、今の天気画面の表示方式は置き換えていません。SHELLに画面案の4ファイルを追加し、オフラインの /weather-design-lab/ と /weather-design-lab/index.html のURLを独立して扱います。
