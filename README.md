# スタンスメモ 独立試作版

公開URL： https://kanon6343.github.io/snowboard-stance-memo-trial/

正式版の /snowboard-stance-memo/ に含まれない場所で試作をインストールできるようにするコピーです。既存の正式版・試作版は変更せずに残します。v2.10.0（試作）、キャッシュ更新1100。

## 公開

このフォルダの中身を新規リポジトリ snowboard-stance-memo-trial のルートへ配置し、GitHub Pages を main ブランチの / (root) から公開します。URLは公開後に検証します。

## データ

同一ブラウザー・同一オリジンであれば haru-detail: の既存データを参照します。別ブラウザーや別ストレージ環境には自動同期しません。既存の試作版でバックアップを書き出しておくと、必要に応じて新しいアプリで復元できます。公開先の分離だけでは同一オリジンのデータ領域は完全には分離されません。

## インストール

新しい試作URLをブラウザーで開き、オフライン準備の完了後、インストール／ホーム画面へ追加します。正式版とはアプリの範囲を重ねない構成です。端末ごとの実機確認は別途行います。

## スタンス幅の検索

「探す」のスタンス幅は「ぴったり／範囲」で切り替えます。ぴったりは53など1つの数値を指定し、53.0は53と同じ幅として扱います。空欄は条件なし。範囲は従来どおり下限・上限を含みます。以前保存した範囲条件は範囲として引き継ぎます。簡易・詳細入力の両方で使え、検索は履歴本体を変更しません。

詳細入力の「探す」では、板の形状（シェイプ・ノーズ形状・ベンド）を折りたたまず常時表示します。簡易入力では非表示です。

更新時は画面HTMLもHTTPキャッシュの再検証を行ってからオフライン用に保存し、連続更新で古い画面が新しいキャッシュに残ることを防ぎます。

## 更新先の表示

更新待ちのService Workerへ直接問い合わせ、更新先の版番号を通知と更新ボタンに表示します。取得できない旧形式の更新は、版番号を推測せず通常の更新ボタンを表示します。今回の機能を読み込んだ後の更新から利用できます。

## 入力と保存履歴のスワイプ

本文を左へ払うと入力から保存履歴へ、右へ払うと保存履歴から入力へ戻ります。タブのタップも使えます。入力途中の値や編集中の内容はそのまま保持し、スワイプで履歴を保存・変更することはありません。画面内の位置は同じ起動中のスワイプ移動で戻れるようにします。

入力欄、ボタン、リンク、ビス穴、左右足の切替、履歴の表示形式、横スクロール部分は対象外。縦スクロール・ピンチとメニューを開く端の操作を優先します。確認画面・ガイド・下書き復元の案内中、メニューを開いている間は画面移動しません。履歴のカード／詳細一覧／板ごとはタップのままです。

メニューで簡易／詳細入力を実際に切り替えた時はメニューを閉じます。起動・下書き復元・ガイドなどのプログラムによるモード変更では閉じません。

## v2.5.0：雪山の天気（はるくん試作）

メニュー→表示→「天気とおすすめ候補を見る」。19地点・7日間の新雪、気温、風を比較し、日付・エリア・お気に入り・バランス／新雪重視／晴れ重視で候補を表示します。営業状況やリフト運行は判定せず、各公式サイトへ案内します。

天気は端末からOpen-Meteoへ直接リクエスト。標準の自動選択モデルへ接続できない場合はGFSアンサンブルのコントロール予報に切り替え、出典を表示します。予報は表示標高付近の予想値で、ゲレンデの実測積雪ではありません。朝の新雪は前日9時より後〜当日9時まで24個の時間値の合計、日中は9〜15時。欠測値は0にせず—を表示します。

新しい設定・予報キャッシュはharu-detail:mountain-weather-*だけを利用し、既存の履歴・入力・バックアップは変更しません。予報キャッシュは1時間で再確認、6時間以上前はおすすめ対象外。APIの応答はこの端末だけに保存し、GitHubへ個人データを送りません。

Weather静的ファイルをオフラインSHELLに含め、weather/とweather/index.htmlの両方を独立したページとして復元します。予報未取得の初回オフライン時は未取得として表示。気象APIはService Workerでキャッシュせず、予報の取得日時と失敗状態を表示します。

予報データ：[Open-Meteo](https://open-meteo.com/)・[CC BY 4.0](https://open-meteo.com/en/licence)。独自の集計・比較で、気象機関の推奨や運休基準ではありません。
